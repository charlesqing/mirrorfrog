## Inference vs Training Optimization

| Dimension | Training | Inference |
|------|------|------|
| **Compute utilization** | Saturated (high batch) | Low (batch 1-32) |
| **Bottleneck** | GPU compute | **Memory + memory bandwidth** |
| **Optimization direction** | Data parallel / model parallel / ZeRO | **KV Cache + attention + batching** |
| **Metric** | tokens/sec (training) | **TTFT, TPOT, throughput** |
| **Typical optimization** | FlashAttention, gradient checkpointing | **PagedAttention, Speculative, quantization** |

> **Inference optimization is more complex than training optimization** — because of latency sensitivity + memory constraints + diverse workloads.

## Three Core Technologies

### 1. PagedAttention (vLLM Core)

**PagedAttention** is the **KV Cache memory management revolution** proposed by the **UC Berkeley team** (Li Zhuohan, @woody-yc, et al.) in the **vLLM paper (SOSP 2023)**.

#### Problem: Traditional KV Cache Waste Is Severe

- **Traditional**: pre-allocate max-length KV Cache per request
- **Example**: 70B model + 4K context = **~2 GB KV Cache / request**
- **100 concurrent requests = 200 GB** — OOM

| Approach | KV Cache Management | Memory Waste |
|------|---------------|----------|
| Traditional (HuggingFace) | Contiguous pre-allocation | **60-80% waste** |
| **PagedAttention** | **Paged on-demand allocation** | **&lt;4% waste** |

#### Principle: OS Paging Idea

```
Traditional:
[req1: 2GB contiguous] [req2: 2GB contiguous] [req3: 2GB contiguous]  -- heavy internal fragmentation

PagedAttention:
[req1: page 0,1,2,3] [req2: page 4,5,6,7] [req3: page 8,9,10,11]  -- page table managed
```

- **Each page = KV Cache of 16 tokens**
- **Allocate pages on demand**, no pre-allocation
- **Page table** tracks the mapping
- **Fragmentation < 4%** (vs 60-80%)

#### Performance Gain

| Metric | Traditional (HF) | **PagedAttention (vLLM)** | Improvement |
|------|-----------|----------------------------|------|
| Throughput (70B inference) | 100 tok/s | **800-1500 tok/s** | **8-15×** |
| Max concurrency | ~30 | **200+** | 6× |
| Memory utilization | 30% | **96%** | 3.2× |
| Long-context support | 4K | **32K-128K** | 8-32× |

> **PagedAttention made vLLM the de-facto standard for LLM inference** — 70B model throughput up 8-15×.

#### Use Cases

- ✅ **High-concurrency online inference** (ChatGPT, Claude, ERNIE)
- ✅ **Long context** (32K+ token)
- ✅ **Multi-model serving** (shared GPU pool)
- ❌ Single-user offline inference (limited gain)

### 2. FlashAttention (GPU Optimization)

**FlashAttention** is the **GPU memory-hierarchy optimization** proposed by **Tri Dao et al.** in 2022.

#### Problem: Attention Matrix O(N²) Memory

- **Standard attention**: must store N×N attention matrix
- **8K context**: 8K×8K = 64M floats = 256 MB
- **32K context**: 32K×32K = 1G floats = **4 GB** — OOM
- **128K context**: 128K×128K = 16G floats = **64 GB** — impossible

#### Principle: Tiling + Recomputation

```
Standard Attention:
Q @ K^T → store N×N matrix → softmax → @ V   -- needs 256MB+ HBM

FlashAttention:
Tiled compute, each tile processed inside SRAM, **no N×N matrix stored**
Q tile × K tile^T → local softmax → × V tile   -- inside SRAM
```

- **Core idea**: **leverage GPU's SRAM (high-speed cache above HBM)**
- **HBM read/write**: from O(N²) down to O(N)
- **Recomputation**: recompute attention in backward pass, don't store intermediates

#### Performance Gain

| Metric | Standard Attention | **FlashAttention v2** | Improvement |
|------|----------------|------------------------|------|
| Training speed | 100% | **200-300%** | 2-3× |
| Memory | O(N²) | **O(N)** | 1/N ratio |
| H100 speed | 600 TFLOPS | **1100+ TFLOPS** | 1.8× |
| 128K context | ❌ OOM | ✅ feasible | — |
| 1M context | ❌ impossible | ✅ FlashAttention-3 | — |

#### FlashAttention Evolution

| Version | Year | Key Improvement |
|------|------|----------|
| **FlashAttention v1** | 2022 | Tiling + recomputation |
| **FlashAttention v2** | 2023 | **Parallelization** + reduced non-matmul work |
| **FlashAttention v3** | 2024 | **FP8 support** + H100 optimization |
| **FlashAttention v4** (est. 2026) | 2026 | Rubin R200 / MI400 optimization |

> **FlashAttention v3 + H100/H200 reaches 1100+ TFLOPS** (FP16) — **exceeding official rated compute**.

#### Use Cases

- ✅ **All attention compute** (training + inference)
- ✅ **Long context** (128K+ token)
- ✅ **GPU inference essential** (H100/B200 standard)
- ❌ Edge devices (no attention optimization needed)

### 3. Speculative Decoding

**Speculative Decoding** is the **inference acceleration technique** proposed by **Leviathan et al. 2023**.

#### Problem: Autoregressive Generation Is Slow

- **LLM generates 1 token at a time**
- **Each token needs a full forward pass**
- **H100 FP16: ~50ms/token** — long generation is slow

#### Principle: Small Model + Large Model Collaboration

```
Traditional:
Large model → token 1 → token 2 → token 3 → ...    -- every token uses large model

Speculative Decoding:
1. Small model (Draft Model) generates 5 candidate tokens at once: [t1, t2, t3, t4, t5]
2. Large model (Target Model) verifies 5 tokens in one forward pass
3. Accept first k matching tokens (k+1 regenerated by large model)
4. Repeat
```

- **Small model**: ~100× faster (70B → 1B)
- **Large model**: verifies multiple tokens in one forward pass
- **Theoretical speedup**: 2-4× (depends on small-model accuracy)

#### Performance Gain

| Metric | Traditional | **Speculative Decoding** | Improvement |
|------|------|--------------------------|------|
| 70B inference speed | 30 tok/s | **60-100 tok/s** | 2-3× |
| TTFT (first token) | 200ms | 200ms (same) | — |
| TPOT (per token) | 33ms | **10-17ms** | 2-3× |
| Applicable models | any | **small + large model** | — |

#### Mainstream Speculative Decoding Schemes

| Scheme | Small model | Speedup | Applicable |
|------|--------|--------|------|
| **Self-Speculative** | same model different layers | 1.5-2× | general |
| **Draft Model** | standalone small (e.g., 7B+70B) | 2-3× | general |
| **Medusa** | multiple decode heads | 2-3× | single model |
| **EAGLE** | feature prediction | 2-3× | single model |
| **Lookahead Decoding** | Jacobi iteration | 1.5-2× | small model |
| **REST** | retrieval-augmented | 2-4× | long generation |

> **vLLM 0.6+ supports Speculative Decoding by default** — simple config, 2-3× performance gain.

#### Use Cases

- ✅ **Large-model offline batch** (most significant effect)
- ✅ **Long output generation** (code, articles, reports)
- ✅ **Multi-turn dialogue** (ReAct, Agent)
- ❌ Very short output (1-5 tokens, limited speedup)

## Other Important Optimization Techniques

### 4. Continuous Batching

**Supported by vLLM / TGI / TensorRT-LLM**:

- **Traditional**: wait for batch to fill before processing, new requests wait
- **Continuous**: dynamically insert new requests into the running batch
- **Gain**: 2-4× throughput

### 5. Quantization

| Precision | Model size | Performance | Quality loss |
|------|----------|------|----------|
| **FP16** | 70B = 140 GB | 1× | 0% |
| **INT8** | 70B = 70 GB | 1.5-2× | &lt;1% |
| **INT4 (GPTQ/AWQ)** | 70B = 35 GB | 2-3× | 1-3% |
| **FP8** | 70B = 70 GB | 1.5-2× | &lt;1% |
| **FP4 (NVFP4)** | 70B = 35 GB | 2-3× | 2-5% |
| **INT2** | 70B = 17.5 GB | 3-5× | 5-15% |

> **NVFP4 (NVIDIA) + quantization-aware training = near-FP16 quality + 2-3× performance**.

### 6. Prefix Caching

- **Scenario**: multiple requests share the same system prompt
- **Method**: cache the KV Cache prefix
- **Speedup**: 0 compute for the shared prefix, **~10-100× speedup**

### 7. Chunked Prefill

- **Problem**: long prompt prefill blocks other requests
- **Method**: chunk the prefill, interleave with decoding
- **Gain**: TTFT -50%, total throughput +20%
