# 机柜即产品：AI 芯片竞争单位从「单卡」变「整柜」

> 看 AI 芯片市场的老习惯是看「出货量多少颗 GPU」。2026 年，这个指标正在失效——头部玩家的竞争单位已经变成**整座机柜**，单卡参数表不再是决策的充分依据。

## 一、各家机柜产品一览

| 厂商 | 机柜/超节点 | 关键口径 |
|---|---|---|
| NVIDIA | Vera Rubin NVL72 | 2026 H2 规模交付，Q4 放量确认 |
| AMD | Helios（MI450） | OpenAI/Meta/微软/Oracle 站点初始系统已运行 |
| 华为 | Atlas 950/960 超节点 | Atlas 950 已发布；960 超节点 9 月官宣 |
| 天数智芯 | 天垓 IXL144 | 单柜 144 GPU、10.1TB 汇聚内存，工博会首展 |
| Meta | MTIA 机架 | 与 MI455X 机架、TPU Pod 并行的组合 |

## 二、为什么竞争单位必须放大

大模型训练的本质是「把几千颗芯片变成一台计算机」。单卡再强，卡间互联带宽与拓扑直径上不去，集群有效算力就会坍缩：

- **Scale-up 域**决定能跑多大的模型：NVL72 把 72 颗芯片连成一个统一内存域；超节点路线（华为 CloudMatrix、天数 IXL144）则用更多卡数换互联规模
- **每瓦有效算力**取代每卡峰值算力成为核心指标：1,800W 的 Rubin R200 与 950W 的 Maia 300，比的是整个机架的 Token 吞吐与功耗比
- **液冷与供电**成为交付约束：吉瓦级数据中心的建设周期里，风冷机柜与液冷机柜的部署密度差一个量级

## 三、瓶颈扩散链

机柜化把瓶颈从芯片扩散到整条供应链：

```
芯片 → HBM/封装(CoWoS-L) → 互联(铜缆/光) → 交换机 → 供电(PSU/母排) → 散热(液冷) → 机房(电力/空间)
```

这正是 2026 年存储涨价、封装紧缺、光模块缺货同时发生的底层原因——**任何单一环节的产能都是整柜交付的瓶颈**。

## 四、选型方法论的变化

1. **以机柜为报价单位**：单卡价格已无意义，问「每机柜交付价 + 每机柜功耗 + 有效 Token 吞吐」
2. **互联架构先于芯片选型**：Scale-up 域大小决定模型规模上限，先定组网再看卡
3. **供应链要逐环节核**：交期不是芯片厂说了算，封装、HBM、光模块、液冷任何一环都可能拖半年
4. **用 TCO 口径横向比**：把机柜价、功耗、PUE、折现统一进模型——这正是本站 [TCO 计算器](/docs/tco-calculator)的设计初衷
